# Organic launch plan

## Positioning

Start with independent agencies that already export an expected ledger and carrier commission statements to spreadsheets. Demonstrate the concrete workflow: import two files, explain an underpayment, trace a source row, export the follow-up report. Do not promise automatic access to carriers, definitive debt recovery or verified support for all countries.

## Search foundation included

Distinct prerendered pages cover the product, reconciliation guide, calculator and templates. Titles, canonical links (when SITE_URL is configured), Open Graph fields, sitemap, robots instructions, semantic HTML and internal links are implemented. No fake testimonials, reviews, customer counts or certification logos are used. Draft/legal and unavailable-account messaging is explicit.

Before launch, configure the exact canonical domain, review indexable content and verify Search Console ownership. Submit the generated sitemap. Confirm that the app/account/API paths stay out of indexing and that production no longer serves the intentional noindex build. Add only schema markup that describes capabilities actually enabled; reviews/ratings must never be fabricated.

## Validate demand before multiplying pages

For the initial four weeks, evaluate these intent clusters: insurance commission reconciliation software; reconcile insurance commissions in Excel; commission statement discrepancies; insurance commission reconciliation template; expected vs received commission calculator. These are hypotheses, not claimed search volumes. Use Search Console query impressions and real free-tool completion to learn which phrasing attracts appropriate users.

One substantial guide should explain due dates, reporting coverage, duplicate quarantine and one-to-many payments with synthetic downloadable examples. Publish a worked problem only when it adds distinct value; do not create country/carrier doorway pages or claim compatibility without testing real representative files.

## Conversion and retention

Provide immediate local reconciliation without signup. Use the synthetic example to demonstrate value. Ask for an account only for cloud features. Before enabling checkout, confirm the paid feature difference is useful enough to justify the price, and remove planned features from any purchased entitlement promise. Current Plus/Pro breadth does not justify treating the commercial scope as finalized.

Measure aggregate funnel events only after an explicit privacy/product decision: tool entry, file mapping completion, run success, export, return visit and paid conversion. Never log policy IDs, file names, raw financial rows or report contents. No analytics or marketing tracking provider is mandatory in this implementation.

Quality acquisition requires indexing, useful content and distribution; a new site is not guaranteed to receive traffic or revenue automatically. Start with a small carrier-file validation cohort and instrument actual repeat use before building dozens of SEO pages.
